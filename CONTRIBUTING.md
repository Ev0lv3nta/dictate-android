# Участие в разработке

Для заметного изменения сначала опишите задачу в issue. Pull request должен решать одну задачу и проходить `./scripts/verify.sh`. Изменения сервиса и аудиотракта проверяются также на эмуляторах; команды есть в [docs/testing.md](docs/testing.md).

Не добавляйте API-ключи, записи голоса, транскрипты, APK, логи и локальные пути. Новые провайдеры должны использовать HTTPS, поддерживать отмену запроса и не писать содержимое аудио или ответа в лог.

В описании PR укажите, что изменилось, как это проверено и требуется ли тест на реальном устройстве.
