# Выпуск версии

1. Обновить `versionCode`/`versionName` приложения и sample, release notes и матрицу проверок.
2. Провести изменения через PR. Проверить CI, эмуляторную матрицу и diff; слить в `main`.
3. Создать тег `v<versionName>` на проверенном commit. Workflow повторно собирает и проверяет проект, затем подписывает оба APK и создаёт черновик релиза.
4. Скачать APK из черновика, проверить обновление, запуск и микрофон. Сверить SHA-256 и сертификат. Только после этого опубликовать релиз (`gh release edit <tag> --draft=false`). Не заменять существующий тег или опубликованные бинарники.

Локальный `assembleRelease` не требует ключа и создаёт unsigned APK. GitHub Environment `release` разрешает только теги `v*`; PR-ветки не имеют доступа к его секретам. Workflow отдельно проверяет, что тег принадлежит `main`. Секреты: `DICTATE_KEYSTORE_BASE64`, `DICTATE_STORE_PASSWORD`; alias — `dictate`. Ключ не генерируется заново при сборке. Владельцу нужна отдельная защищённая резервная копия ключа и пароля вне Git: без прежнего сертификата обычное обновление APK невозможно.

SHA-256 сертификата:

```text
DA:5D:4D:BF:AE:BE:11:AE:A9:79:BA:7D:BA:21:2F:0C:59:45:73:29:13:AA:61:DB:2C:90:D0:62:D6:59:0C:00
```

Проверка скачанных файлов: `sha256sum -c SHA256SUMS`, затем `apksigner verify --verbose --print-certs dictate.apk`. В macOS вместо `sha256sum` можно использовать `shasum -a 256 -c SHA256SUMS`.

`v0.1.0` был неподписанным техническим артефактом, не устанавливаемым релизом. Проверка обновления новой версии не означает миграцию с личной сборки или с несуществовавшего подписанного `v0.1.0`.
